# Validate Binary Search Tree

<Difficulty level="Medium" />

> **LeetCode 98** – [Validate Binary Search Tree](https://leetcode.com/problems/validate-binary-search-tree/) | **Striver (TUF)** – [Check if a Tree is a BST or Not](https://takeuforward.org/data-structure/check-if-a-tree-is-a-bst-or-bst-or-not/)

## Problem Statement

Given the `root` of a binary tree, determine if it is a valid **binary search tree (BST)**.

A valid BST requires:

- The left subtree of a node contains only values **strictly less** than the node.
- The right subtree contains only values **strictly greater** than the node.
- Both subtrees are themselves valid BSTs.

### Examples

| # | Input | Output |
|---|-------|--------|
| 1 | `root = [2,1,3]` | `true` |
| 2 | `root = [5,1,4,null,null,3,6]` | `false` |

### Constraints

- The number of nodes is in the range `[1, 10⁴]`.
- `-2³¹ <= Node.val <= 2³¹ - 1`

---

## Approaches (Striver / TUF progression)

| # | Approach | Time | Space |
|---|----------|------|-------|
| 1 | Naive — compare each node with its children only | — | — | 
| 2 | Inorder traversal must be strictly increasing | $O(n)$ | $O(n)$ |
| 3 | **Range / bounds propagation (optimal)** | $O(n)$ | $O(h)$ |

### Approach 1 — Why the obvious check fails

Checking only `node.left.val < node.val < node.right.val` is **wrong**. In `[5,1,4,null,null,3,6]` the pair `(4, 3)` looks locally fine, yet 3 sits in 5's right subtree where everything must exceed 5.

### Approach 2 — Inorder traversal

An inorder traversal of a valid BST yields a **strictly increasing** sequence. Traverse, collect the values, and verify each is larger than the previous.

```js
var isValidBSTInorder = function(root) {
    let prev = null, ok = true;
    const inorder = (node) => {
        if (!node || !ok) return;
        inorder(node.left);
        if (prev !== null && node.val <= prev) ok = false;
        prev = node.val;
        inorder(node.right);
    };
    inorder(root);
    return ok;
};
```

### Approach 3 — Bounds propagation (optimal)

Carry a valid `(min, max)` interval down the recursion, tightening it at each turn. It catches violations as early as possible and needs no extra array.

## Solution

**Approach (bounds propagation):** Checking only `left < node < right` locally is **not enough** — a deep descendant can still violate an ancestor's constraint. Instead, carry an open interval `(min, max)` down the recursion:

- Going **left**, the upper bound tightens to the current node's value.
- Going **right**, the lower bound tightens to the current node's value.

A node is valid only if its value lies strictly inside its inherited interval.

- **Time Complexity:** $O(n)$ — each node is checked once.
- **Space Complexity:** $O(h)$ — recursion stack.

<Tabs groupId="lang">
<TabItem value="js" label="JavaScript">

```js
/**
 * @param {TreeNode} root
 * @return {boolean}
 */
var isValidBST = function(root) {
    const validate = (node, min, max) => {
        if (node === null) return true;
        if (min !== null && node.val <= min) return false;
        if (max !== null && node.val >= max) return false;
        return validate(node.left, min, node.val) &&
               validate(node.right, node.val, max);
    };
    return validate(root, null, null);
};
```

</TabItem>
<TabItem value="java" label="Java">

```java
class Solution {
    public boolean isValidBST(TreeNode root) {
        return validate(root, null, null);
    }

    private boolean validate(TreeNode node, Integer min, Integer max) {
        if (node == null) return true;
        if (min != null && node.val <= min) return false;
        if (max != null && node.val >= max) return false;
        return validate(node.left, min, node.val)
            && validate(node.right, node.val, max);
    }
}
```
